# Codex 额度容量估算（测试版）

## 数据与范围

只使用身份已确认的账号云端累计 tokens，记录同次刷新中的通用 Codex 额度；同次读取不代表两者统计截止时间同步，不把本机会话与云端总量相加。仅识别明确返回的 300 分钟和 10080 分钟窗口，不按订阅名称猜测窗口，也不将未知窗口视为周额度。

观测按账号、观察时间存入 SQLite，重复观测幂等。原始观测持久化，历史周期从原始记录重算，避免只保存不可审计的估算结果。旧的每日 tokens 不自动回填为周期容量。

## 周期与容量

每个窗口独立维护周期。自然重置、提前恢复（包括截止时间不变但已用百分比显著下降）、实际套餐变更会切分周期。提前恢复没有原因证据时不声称由官方或重置卡触发。

同一段用量可以分别衡量两个限制，但账户实际用量只计一次。跨周重置的累计 tokens 差不能分配给新旧周周期，却仍可用于未跨重置的 5 小时窗口。

有效区间容量为 `100 × Σtokens增量 / Σ已用百分比增量`。不要求起始百分比为零。每个连续区间保留最初有效起点，云端累计 tokens 增长时，用起点至当前观测的累计差更新整段贡献（替换而非重复累加）；至少变化 2 个百分点且 tokens 增加才纳入，合计至少 10 个百分点才显示容量。

仅 tokens 读取失败而额度窗口仍连续时，保留起点与已观察到的额度变化。tokens 长时间不更新时保留上次估算，不把新的百分比消耗追加到旧 tokens 的分母，界面简短提示“等待云端用量”。计数回退、百分比小幅修正或缺少额度窗口仍会断开当前配对。未记录时段不均摊、不补零。

如果重置前存在尚未匹配的额度消耗，重置后的第一次迟到 token 增量可能混有旧周期用量：不将该增量分配给任一周期，而在它返回后建立新的起点；如果该增量已在跨重置的那次观测里返回，则在边界直接跳过。另一个没有重置的窗口仍可独立使用同一批数据。满额且尚未使用时，截止时间随刷新顺延不再生成额外的空周期；超过先前截止时间的观测缺口仍按新周期处理。

剩余 tokens 为 `容量 × 当前剩余百分比 / 100`；窗口过期或未返回时不显示其当前剩余预测。临时缺失不删除旧历史。

历史环比为 `(本周期容量 / 上周期容量 − 1) × 100%`。套餐变更或缺失整个周期时不连接跨阶段环比。没有用满的提前重置周期仍能估算，不按周期天数扩成七天。

## 下一周期

分别取同一账号、同一窗口、当前订阅阶段最近至多五个连续有效已结束周期。相邻变化比例的中位数代表近期方向，只有最近两次变化同向且中位数同向，才延续一半变化：

`下一周期 = 最近周期容量 × (1 + 0.5 × 变化比例中位数)`

不足三个周期或趋势反转时沿用最近水平，不把一次下降直接外推。100、80、64 得到 57.6；100、120、144 得到 158.4；100、50 暂估 50。以上窗口数量、百分比门槛和 0.5 均为初始参数，不是经实测验证的最优参数。应使用后续真实周期与“沿用最近水平”的基线比较预测误差，再调整。

## 限制

总 tokens 与额度接口可能有延迟、回补及统计范围差异，单靠累计计数无法验证所有隐性补记；因此展示的是按使用方式估算的容量，不是官方额度或确认的服务器降额。切换模型、缓存比例、速度或共享额度功能可能改变结果。需要更完整服务端明细才能进一步归因或精确回填。

示例预览只在内存中生成，并使用同一个算法，不写入账号历史。界面支持简体中文、英文及项目其余八种语言。
